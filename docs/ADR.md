# 결정과 확인 항목

## 사용자 요구

앱에서 사용자가 직접 국내주식 실주문을 내고, 체결·잔고를 축적해 온톨로지와 GraphRAG로 질의한다. 초기 연결 검토 대상은 미래에셋증권이다. AI 기능은 OpenAI API 키 없이 로컬 ChatGPT 로그인으로 `codex exec`를 동기 호출한다.

## 주문 연결

이 프로젝트는 미래에셋증권 개인 계좌용 국내주식 주문 연결을 구현하거나 검증하지 않았다. 신청 경로·명세·지원 여부는 미확인 상태다. 미래에셋 공식 채널에서 개인 앱 등록, 실주문, 취소·정정, 체결 및 잔고 조회, 테스트 환경을 확인하는 것이 첫 연결 작업이다. 체결 파일 가져오기는 사용자가 내보낼 수 있는 실제 형식이 확인되면 별도 입력으로 연결한다. [미래에셋증권](https://securities.miraeasset.com/)

미래에셋 연결이 불가능하다고 확인되면 공식 주문 API가 문서화된 증권사 어댑터를 검토한다. 후보를 채택할 때는 사용자 계좌 선택과 테스트 환경을 확인한다. [한국투자증권 KIS Developers](https://apiportal.koreainvestment.com/intro)

## 저장소와 서비스 경계

한 Git 저장소에 React UI(`apps/web/`), Spring Boot 거래 서비스(`services/trading/`), Python 근거 검색·설명 서비스(`services/research/`), 공용 HTTP 계약(`contracts/`)을 둔다. 계약과 양쪽 구현을 한 변경에서 검토하고 첫 화면의 통합 동작을 함께 검증할 수 있다. 서비스는 각각 실행되므로 실행 환경과 HTTP 장애를 따로 다뤄야 한다.

거래 서비스가 주문·체결·원장에 대한 쓰기 권한과 거래 사실의 책임을 갖는다. 브라우저는 거래 서비스의 API를 호출한다. 거래 서비스는 질문과 필요한 근거만 Python 서비스에 전달하고, Python 서비스는 답변과 근거 ID를 반환한다. Python 서비스에는 거래 원장 접근 권한과 주문 도구를 주지 않는다. 질의 서비스 장애가 생겨도 체결 조회는 가능해야 한다.

그래프는 종목·거래·공시·주제·사용자 메모의 출처와 발생 시각을 연결한다. GraphRAG는 질문에 필요한 항목만 정제해 Codex에 전달한다. 원장 DB와 그래프 DB는 구현 단계에서 결정한다. 증권사 API는 어댑터 뒤에서 연결한다.

서비스 내부의 의존성 방향은 각 언어의 정적 검사나 빌드 테스트로 검증한다. 브라우저 기능이 화면 조립 코드에 기대거나, 거래 계산과 근거 처리 코드가 HTTP·저장소·모델 실행 구현에 기대면 외부 환경 없이 테스트하기 어려워진다. 기능을 조립하는 부분에서 구현을 연결하고, 핵심 로직의 의존성은 [개발 품질 검사](development-quality.md#코드-의존성-경계)로 제한한다.

브라우저용 HTTP 경로는 `/api/v1/`, Java와 Python 사이의 경로는 `/internal/v1/`로 시작한다. 기존 호출을 깨는 변경이 필요할 때 새 경로 버전을 만들 수 있고, 호환되는 변경은 같은 버전에서 다룬다. 내부 계약에도 버전을 두는 이유는 두 서버를 별도로 실행하고 변경하기 때문이다.

첫 화면의 인수 기준과 작업 범위는 [FIRST_DEMO.md](../FIRST_DEMO.md)에 둔다.
