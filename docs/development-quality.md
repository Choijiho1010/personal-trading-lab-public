# 개발 품질 관리

## 검증 흐름

| 시점 | 검사 |
|---|---|
| pre-commit | 스테이징된 내용의 비밀·금지 경로, Python 정적 검사, 파일 형식과 소스 주석, 관련 파일 변경 시 오류 경계 검사 |
| pre-push | 전송 커밋의 파일·이력 검사, 전체 정적 검사와 합성 테스트 |
| CI | 추적 파일·전체 이력의 비밀 검사와 동일한 프로젝트 검사 |
| PR | Codex 자동 리뷰와 중대한 지적 해결 |

Python 3.9 이상, uv 0.13.5, Gitleaks 8.24.2를 사용한다. 직접 의존성은 정확한 버전으로 고정하고 `uv.lock`으로 전이 의존성을 고정한다.

```sh
git init -b main
uv sync --frozen
python3 scripts/setup_dev.py
uv run --frozen python scripts/quality.py check
uv run --frozen python scripts/quality.py audit
```

`setup_dev.py`는 Git 저장소에서 pre-commit과 모든 전송 ref를 읽는 pre-push Hook을 설치한다. 전송 커밋을 체크아웃하고 추적 파일의 변경을 정리한 상태에서 푸시한다. 검사 도구가 없거나 검사가 실패하면 통과시키지 않는다. Hook은 우회할 수 있으므로 병합 기준은 CI에서도 검증한다. CI 기본 테스트는 외부 모델 호출과 인증을 요구하지 않는다.

첫 데모 질의 서비스의 Import Linter와 합성 HTTP 테스트는 루트 품질 검사에서 실행한다. CI 워크플로에는 React 린트·테스트·빌드, Java API·ArchUnit 테스트와 실행 JAR 빌드, 로컬 HTTP 성공·시간 초과 검사도 포함한다. 같은 실행 경로는 [첫 데모 실행 방법](../README.md#로컬에서-첫-데모-실행)을 따른다.

### 오류 경계 검사

`uv run --frozen pre-commit run error-boundary --all-files`로 훅을 재현한다. OpenAPI의 오류 상태·코드와 요청 ID 헤더를 확인하고, 가짜 Codex 프로세스 실패 시 CLI가 원문을 표준 오류에 출력하지 않는지 검사한다. 같은 테스트는 CI 기본 품질 검사에서도 실행된다. 서비스 구현 시에는 [첫 데모 명세](../FIRST_DEMO.md#오류-응답과-서비스-로그)의 실제 HTTP 실패·요청 ID 전달·서비스 로그 검사를 추가한다.

## 코드 의존성 경계

React, Java, Python은 각자의 빌드와 실행 환경을 사용한다. 서비스 간 연결은 저장소의 [공용 HTTP 계약](../contracts/first-demo.openapi.yaml)을 따른다. 각 빌드에서 소스 루트와 패키지 해석 범위를 자기 서비스에 두고, 다른 서비스 소스 폴더를 참조 경로에 추가하지 않는다.

| 영역 | 허용 방향과 금지 예시 | 검사 |
| --- | --- | --- |
| React | 앱 진입점이 기능을 조립한다. 기능 코드가 앱 진입점을 역참조하거나, 여러 기능이 있을 때 다른 기능의 내부 파일을 직접 import하는 것을 금지한다. 공용 UI는 기능 코드에 의존하지 않는다. | ESLint의 [`import/no-restricted-paths`](https://github.com/import-js/eslint-plugin-import/blob/main/docs/rules/no-restricted-paths.md). TypeScript 별칭을 쓸 때 같은 규칙이 상대 경로와 별칭에 적용되도록 해석기를 설정한다. |
| Java | HTTP 계층은 거래 로직을 호출한다. 거래 도메인에서 컨트롤러, 저장소 구현, Python HTTP 클라이언트, Spring 패키지로의 의존을 금지한다. 구성 코드는 구현을 연결할 수 있다. | JUnit에 [ArchUnit](https://www.archunit.org/userguide/html/000_Index.html)을 연결한다. 소스의 import 문뿐 아니라 컴파일된 클래스의 타입 의존성도 검사한다. |
| Python | HTTP 어댑터와 Codex 실행 연결부는 질의 핵심을 호출할 수 있다. 질의 핵심에서 HTTP 프레임워크, Codex 실행 어댑터, 앱 구성으로의 의존을 금지한다. 질의 서비스에 거래 서비스나 루트 실험 스크립트의 직접 import를 두지 않는다. | [Import Linter의 Forbidden 계약](https://import-linter.readthedocs.io/en/stable/contract_types/forbidden/)으로 패키지의 정적 의존성을 검사한다. 외부 패키지까지 규칙에 넣을 때는 외부 패키지 분석을 활성화한다. |

각 서비스의 최초 구현에 해당 검사와 합격·실패 사례를 넣는다. React는 유효한 의존성과 상대 경로·별칭으로 우회한 import를, Java와 Python은 정상 호출 방향과 역방향 의존을 검증한다. 주 담당자가 로컬 품질 검사와 필수 `quality` CI에 명령을 연결한다. 서비스가 생성된 뒤에는 대상 패키지나 도구가 누락되면 실패하도록 연결한다. 정적 검사와 별도로 HTTP 인수 테스트에서 실제 호출 방향과 전달 필드를 검증한다.

첫 데모 명세에는 워커가 시작 전에 읽을 성공 기준과 공유 입력을 두고, 로컬 검사에서 빠르게 판정할 수 있는 항목은 도구에 맡긴다. 합성 서비스가 준비되면 브라우저에서 정상 흐름과 실패 복구를 확인한다. [Eugene Yan의 위임과 검증 사례](https://eugeneyan.com/writing/working-with-ai)

## 공개 데이터 경계

실제 계좌·인증·거래 데이터는 레포 밖에 저장한다. 환경 예시에는 가짜 값만 둔다. 합성 fixture·스키마·평가셋·의존성 잠금 파일은 공개한다. `.gitignore`는 이미 추적된 파일과 과거 이력을 제거하지 않는다. 최초 공개 전 `audit`으로 전체 이력을 검사한다.

금지 경로 검사는 계좌 원본·인증·실행 기록의 지정 경로를 차단한다. Gitleaks는 알려진 비밀 패턴을 찾으며 모든 계좌 식별자나 개인정보 탐지를 보장하지 않는다. 실제 데이터를 합성 자료로 바꾸는 작업을 비밀 탐지로 대체하지 않는다.

공개 문서는 목적·설계 결정·실행 방법·검증 결과·한계를 설명한다. 코드의 설명 주석은 제거하고, 도메인 제약은 테스트에서 검증한다. 파일 검사와 전체 품질 검사는 Python 및 YAML의 주석에 파일명과 줄 번호를 표시하며 실패한다. 첫 줄의 실행기 지시(`#!`)와 문자열 안의 `#`은 허용한다.

## 푸시 전 공개 적합성 점검

구현자는 원격 전송 전에 다음 항목을 직접 확인한다. 비밀 검사 통과만으로 공개 적합성을 판정하지 않는다.

- 전송할 파일과 전체 Git 이력에 개인 설정·운영 기록·실제 계좌/거래 자료가 없는지 확인한다. 작성자와 커미터 이메일은 사용자가 선택한 공개용 주소인지 확인한다. 실제 연락처 공개를 원하지 않는 경우에는 noreply 주소를 사용한다.
- 문서·주석·커밋 메시지·PR 본문에서 개인 호칭·대화 흔적·로그인/권한 문제·계정 할당량·비공개 문서와 근거 링크를 제거한다.
- 구현 범위와 검증 결과를 실제 실행한 명령·대상 커밋에 맞춘다. 다른 저장소의 CI·보호·리뷰 결과를 현재 저장소의 완료 근거로 사용하지 않는다. Codex 의존성·외부 전송·합성 자료·미확인 사항은 명시한다.
- 품질·내용·이력 검사를 통과한 정확한 커밋만 푸시한다. 이후 내용이나 커밋 메타데이터가 바뀌면 해당 점검을 다시 수행한다.

상세 점검 과정은 Git에서 제외한 로컬 기록에 보관하고, 단계 파일에는 재현 가능한 결과와 공개 근거만 남긴다. 이 점검은 구현자의 자체 점검이며 로컬 AI 리뷰나 별도 리뷰 에이전트를 실행하지 않는다. AI 리뷰는 GitHub PR에서 수행한다.

## PR 운영

PR 템플릿에 변경 이유, 검증 명령·결과, 남은 한계를 기록한다. GitHub에서 Codex 저장소 연결 후 자동 리뷰를 활성화한다. 앱과 CI에 API 키나 ChatGPT 인증 파일을 추가하지 않는다. Git Hook과 로컬 백그라운드 작업에서는 AI 리뷰를 실행하지 않는다.

`main`에 PR과 `quality` CI 성공을 요구하고 직접 푸시·강제 푸시를 제한한다. 이 설정은 원격 저장소의 ruleset 또는 branch protection에서 적용한다. Codex 리뷰 게시와 필수 상태 체크는 별개다. 최신 커밋에 대한 리뷰·재리뷰와 병합 차단을 테스트하기 전에는 자동 AI 게이트가 검증됐다고 기록하지 않는다. AI 지적은 재현 근거로 판단하며 비밀·주문 중복·원장 훼손 등 P0은 병합 전에 해결한다.

## 완료 조건

가짜 비밀 차단, 합성 자료 허용, 새 환경에서 검사 재현, 실패 응답·잘못된 근거 거부, 미래 근거의 입력 전 제외를 검증한다. 설정 파일 작성, Hook 설치, CI 실행, 원격 보호 활성화 상태를 각각 기록한다. 합성 검증은 실계좌 검증이 아니다.

Gitleaks는 공식 릴리스의 8.24.2 바이너리를 설치한다. Go가 있는 환경에서는 다음 명령도 사용할 수 있다.

```sh
go install -ldflags "-X github.com/zricethezav/gitleaks/v8/cmd.Version=8.24.2" github.com/zricethezav/gitleaks/v8@v8.24.2
```

의존성을 변경할 때는 `uv lock`으로 잠금 파일을 갱신하고 전체 검사를 실행한다.
