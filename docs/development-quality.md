# 개발 품질 관리

## 검증 흐름

| 시점 | 검사 |
|---|---|
| pre-commit | 스테이징된 내용의 비밀·금지 경로, Python 정적 검사, 파일 형식 |
| pre-push | 전송 커밋의 파일·이력 검사, 전체 정적 검사와 합성 테스트 |
| CI | 추적 파일·전체 이력의 비밀 검사와 동일한 프로젝트 검사 |
| PR | Codex 자동 리뷰와 중대한 지적 해결 |

Python 3.9 이상, uv 0.13.5, Gitleaks 8.24.2를 사용한다. 직접 의존성은 정확한 버전으로 고정하고 `uv.lock`으로 전이 의존성을 고정한다.

```sh
git init -b main
uv sync --frozen
python3 scripts/setup_dev.py
uv run --frozen python scripts/quality.py check
uv run --frozen python scripts/quality.py audit
```

`setup_dev.py`는 Git 저장소에서 pre-commit과 모든 전송 ref를 읽는 pre-push Hook을 설치한다. 전송 커밋을 체크아웃하고 추적 파일의 변경을 정리한 상태에서 푸시한다. 검사 도구가 없거나 검사가 실패하면 통과시키지 않는다. Hook은 우회할 수 있으므로 병합 기준은 CI에서도 검증한다. CI 기본 테스트는 외부 모델 호출과 인증을 요구하지 않는다.

## 공개 데이터 경계

실제 계좌·인증·거래 데이터는 레포 밖에 저장한다. 환경 예시에는 가짜 값만 둔다. 합성 fixture·스키마·평가셋·의존성 잠금 파일은 공개한다. `.gitignore`는 이미 추적된 파일과 과거 이력을 제거하지 않는다. 최초 공개 전 `audit`으로 전체 이력을 검사한다.

금지 경로 검사는 계좌 원본·인증·실행 기록의 지정 경로를 차단한다. Gitleaks는 알려진 비밀 패턴을 찾으며 모든 계좌 식별자나 개인정보 탐지를 보장하지 않는다. 실제 데이터를 합성 자료로 바꾸는 작업을 비밀 탐지로 대체하지 않는다.

공개 문서는 목적·설계 결정·실행 방법·검증 결과·한계를 설명한다. 주석에는 구현 이유와 도메인 제약을 쓰고 개인 작업 지시나 비공개 문서 참조를 남기지 않는다.

## 푸시 전 공개 적합성 점검

구현자는 원격 전송 전에 다음 항목을 직접 확인한다. 비밀 검사 통과만으로 공개 적합성을 판정하지 않는다.

- 전송할 파일과 전체 Git 이력에 개인 설정·운영 기록·실제 계좌/거래 자료가 없는지 확인한다. 작성자와 커미터 이메일은 공개용 noreply 주소를 사용한다.
- 문서·주석·커밋 메시지·PR 본문에서 개인 호칭·대화 흔적·로그인/권한 문제·계정 할당량·비공개 문서와 근거 링크를 제거한다.
- 구현 범위와 검증 결과를 실제 실행한 명령·대상 커밋에 맞춘다. 다른 저장소의 CI·보호·리뷰 결과를 현재 저장소의 완료 근거로 사용하지 않는다. Codex 의존성·외부 전송·합성 자료·미확인 사항은 명시한다.
- 품질·내용·이력 검사를 통과한 정확한 커밋만 푸시한다. 이후 내용이나 커밋 메타데이터가 바뀌면 해당 점검을 다시 수행한다.

상세 점검 과정은 Git에서 제외한 로컬 기록에 보관하고, 단계 파일에는 재현 가능한 결과와 공개 근거만 남긴다. 이 점검은 구현자의 자체 점검이며 로컬 AI 리뷰나 별도 리뷰 에이전트를 실행하지 않는다. AI 리뷰는 GitHub PR에서 수행한다.

## PR 운영

PR 템플릿에 변경 이유, 검증 명령·결과, 남은 한계를 기록한다. GitHub에서 Codex 저장소 연결 후 자동 리뷰를 활성화한다. 앱과 CI에 API 키나 ChatGPT 인증 파일을 추가하지 않는다. Git Hook과 로컬 백그라운드 작업에서는 AI 리뷰를 실행하지 않는다.

`main`에 PR과 `quality` CI 성공을 요구하고 직접 푸시·강제 푸시를 제한한다. 이 설정은 원격 저장소의 ruleset 또는 branch protection에서 적용한다. Codex 리뷰 게시와 필수 상태 체크는 별개다. 최신 커밋에 대한 리뷰·재리뷰와 병합 차단을 테스트하기 전에는 자동 AI 게이트가 검증됐다고 기록하지 않는다. AI 지적은 재현 근거로 판단하며 비밀·주문 중복·원장 훼손 등 P0은 병합 전에 해결한다.

## 완료 조건

가짜 비밀 차단, 합성 자료 허용, 새 환경에서 검사 재현, 실패 응답·잘못된 근거 거부, 미래 근거의 입력 전 제외를 검증한다. 설정 파일 작성, Hook 설치, CI 실행, 원격 보호 활성화 상태를 각각 기록한다. 합성 검증은 실계좌 검증이 아니다.

Gitleaks는 공식 릴리스의 8.24.2 바이너리를 설치한다. Go가 있는 환경에서는 다음 명령도 사용할 수 있다.

```sh
go install -ldflags "-X github.com/zricethezav/gitleaks/v8/cmd.Version=8.24.2" github.com/zricethezav/gitleaks/v8@v8.24.2
```

의존성을 변경할 때는 `uv lock`으로 잠금 파일을 갱신하고 전체 검사를 실행한다.
