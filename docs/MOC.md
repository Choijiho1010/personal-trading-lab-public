# 문서 목차

현재 구현 범위와 후속 조건은 단계 파일을 기준으로 확인한다. 사례에서 도출한 제안과 확정된 결정을 구분한다.

- [단계와 완료 조건](../phases/index.json): 현재 상태, 재현 근거, 미확인 항목.
- [결정과 확인 항목](ADR.md): 제품 요구, 증권사 연결 현황, 서비스 경계.
- [첫 데모 구현 명세](../FIRST_DEMO.md): 화면 동작, HTTP 계약, 합성 예시, 인수 기준.
- [인수 기준](RUBRIC.md): 주문·원장·근거·Codex 실행의 완료 판단.
- [개발 품질 관리](development-quality.md): 검사, Hook, CI, 공개 데이터 경계와 PR 운영.
- [금융 AI 사례를 하네스 설계에 적용하기](ai-case-study-insights.md): 토스증권·NAVER·우아한형제들 원문과 적용 후보, 합성 평가 항목.

## 기술 블로그 탐색 출처

- [Eugene Yan](https://eugeneyan.com/)의 [주제별 안내](https://eugeneyan.com/start-here)와 [전체 글](https://eugeneyan.com/writing)에서 LLM 평가, 검색·추천, ML 시스템 운영, AI 개발 협업을 조사한다. 시작점으로 [LLM Evaluators](https://eugeneyan.com/writing/llm-evaluators), [Improving RecSys & Search with LLMs](https://eugeneyan.com/writing/recsys-llm), [How to Work and Compound with AI](https://eugeneyan.com/writing/working-with-ai)를 참고한다.
- 국내 금융 서비스와 개발 운영 사례는 [금융 AI 사례 문서](ai-case-study-insights.md)의 토스증권·NAVER D2·우아한형제들 원문에서 주제에 따라 찾아본다.

설계에 적용하는 사례는 읽은 원문, 적용 대상, 확인할 결과를 함께 기록한다.
